# 记忆与上下文设计

- 日期：2026-11-04
- 关联步骤：无（为第 3 步及之后的 playbook 设计做准备）

## 改动内容

- `docs/architecture.md`：
  - 新增第 8 节“记忆与上下文”：分层（运行上下文、运行记录、playbook、learnings、数据集与报告）、7 条规则、上下文长度策略。原第 8~10 节顺延为第 9~11 节。
  - 第 3.2 节：收尾调用改为带工具定义并设 `tool_choice: "none"`，收尾说明附加在最后一条还没发出的工具结果上；`timeout`、`aborted` 不做收尾调用。
  - 第 3.5 节：每个运行事件都带 `run_id`，工具事件增加 `step`、`call_id`，模型事件增加 `final`、`tool_calls`。
  - 第 9 节目录结构加入 `test/`。

## 设计决定

- 参考 Hermes Agent 的记忆设计：有字数上限、只能通过工具写入、运行开始时冻结快照、检索返回原文。
- ugc-lens 记住的是分析经验，所以 playbook 对应 Hermes 的 `MEMORY.md`，learnings 和运行记录对应它的会话检索；暂时不需要 `USER.md` 那样的用户画像。
- 收尾调用不插入伪造的 user 消息，遵守“循环中不伪造消息、不改历史”的规则。
- 第一版不做上下文压缩，靠工具结果截断、分页和步数上限控制长度。
