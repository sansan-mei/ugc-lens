# init命令与全局配置

- 日期：2026-11-05
- 关联步骤：roadmap 第 10.5 步（init 进 0.0.2）

## 改动内容

- `src/config.ts`：`loadLlmConfig` 读取全局配置 `~/.ugc-lens/config.json`（第三个参数可注入 home 目录），优先级 参数 > 环境变量 > 项目配置 > 全局配置 > 预设；`LlmConfigFile` 新增 `api_key`；导出 `loadDotEnv`、`readGlobalConfig`、`writeGlobalConfig`（替换 llm 字段、保留其他顶层字段、权限 600）；缺提供商或 key 的错误信息里提示 `ugc-lens init`。
- 新增 `src/cli/init.ts`：`ugc-lens init` 交互式初始化。选提供商（编号或 id）→ 双地址提供商问区域 → 填 API key（ollama 不问；环境变量已有或已保存的可回车保持）→ `GET /models` 列出模型供选择，失败改手动输入 → 发一次强制工具调用的测试（顺便验证 function call）→ 写入全局配置。流程函数 `runInitFlow` 的输入输出、模型列表、测试调用都可注入。
- `src/cli/index.ts`：接入 `init`，总用法里列出。
- 文档：`docs/providers.md` 第 1、4 节（全局配置、`api_key` 字段、新优先级）；`docs/architecture.md` 第 2.2 节；README；`docs/roadmap.md` 第 10.5 步笔记。

## 设计决定

- 用户决定：`init` 进 0.0.2，不影响已发布的 0.0.1；配置写到全局目录 `~/.ugc-lens/`。
- key 写进全局配置文件（权限 600）：全局目录不在 git 仓库里，没有误提交风险。项目配置仍只写 `api_key_env`，文档里说明项目配置放 key 有被误提交的风险。
- 不内置默认模型名（providers.md 原定）：用 `GET /models` 的真实列表，最多显示 30 个，也可以直接输入名字。
- 测试调用用强制工具调用：一次调用同时验证 key、模型名和 function call 支持。失败时不阻止保存，由用户决定。
- 整个流程共用一个 readline 接口：每个问题新建接口会把用户一次粘贴的多行回答丢掉（pty 实测复现）。
- 放弃：key 输入不回显（readline 做起来复杂，本地终端风险低）；全局 `.env`（用户选了 config.json）。
