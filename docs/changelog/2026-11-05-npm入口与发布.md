## 设计决定

- 用户决定：版本 0.0.1；命令行带 `watch`、`analyze`、`ask`；第一次由用户在本机发布，之后 CI 用 Trusted Publishing；`package.json` 版本号变化时发布。MCP 延后。
- 发布编译后的 JS，不发布 `.ts`：Node 不对 `node_modules` 里的 `.ts` 做类型剥离。开发时仍直接运行 `.ts`。
- 用 `tsc` 编译加一个小脚本修声明文件，不引入 tsup 等打包工具，保持依赖少。
- 发布触发：push 到 master 且改了 `package.json` 时运行，再检查这个版本在 npm 上是否已存在，所以只改依赖不改版本号不会发布；也可以在 Actions 页面手动运行。
- `prepublishOnly` 跑类型检查、测试、编译，本机发布和 CI 发布走同一套检查。
- 工作流里的 action 和 npm 都写精确版本，和依赖的规则一致。
- 放弃：CLI 读全局配置目录（如 `~/.config/ugc-lens`），第一版仍按当前目录读 `.env` 和 `.ugc-lens/`。
