## 改动内容

- 模型客户端（`src/llm/`）：
  - `tool_choice` 可以指定必须调用的工具。
  - 解析提示词缓存命中的 token（DeepSeek 的 `prompt_cache_hit_tokens`、OpenAI 的 `prompt_tokens_details.cached_tokens`），统一为 `usage.cached_input_tokens`。
  - `disableThinking`：按提供商预设的 `thinkingOff` 关闭思考模式（DeepSeek、智谱、通义千问）。
  - 发送前把半个代理对换成 U+FFFD。
  - 新增 `tokens.ts`：`approxTokens` 粗略估计 token 数。
- 假模型（`src/agent/fake_model.ts`）：指定工具时没有调用或调用了别的工具，视为剧本错误。
- 分块（`src/pipeline/chunk.ts`）：
  - 每块用短编号 `[1]`、`[2]`… 代替原 ID，`ids[n-1]` 对应编号 n。
  - 行格式去掉内容类型和回复关系，保留赞、回复数、日期、IP 属地、用户名；去掉“回复 @某人 :”；多个内容时用 `@1`、`@2` 标出。
  - 低信息内容（`isLowInfo`：去掉表情和标点后不超过 3 个字，且没有赞、回复、复读）只计数不放进块里，覆盖率里新增 `low_info`。
  - 默认总字数从 24 万改为 8 万（`DEFAULT_MAX_TOTAL_CHARS`）。
- `src/analysis/text.ts`：新增 `stripReplyPrefix`、`isLowInfo`。`src/tools/data/format.ts`：新增 `sliceText`，截断时不拆开 emoji。
- 新增 `src/pipeline/summarize.ts`：`summarizeChunks`（每块一次调用、并发默认 4、token 预算、取消、进度回调）、`estimateSummarize`、`parseFindings`（校验编号和摘句并换回原 ID）、`buildSystemPrompt`。
- 示例：新增 `examples/09_summarize.ts`、`npm run summarize`，加进 `npm run smoke`；`examples/09_chunks.ts` 显示低信息内容条数。

## 设计决定

- 用户要求整个分析尽量少用 token、多用代码。由用户决定的四点：引用只给编号，被引用的内容超过 80 字才附摘句（摘句是输出 token，比输入贵）；默认交给模型 8 万字；低信息内容只计数；用户名、日期、IP 属地照发（用户指出地区本身就是要分析的信息，推翻了先前“都不发”的选择）。
- 每块只调用一次模型，不走 Agent 循环。走循环的话，工具结果返回后还要再调用一次模型。
- 格式错误不请模型重试：重试要把整块内容再发一遍。代码逐条校验，保留合格的观点，丢掉的按原因计数。
- 引用校验放在分块总结这一步：块内编号只有在这一块里才有意义，换回原 ID 时顺便检查编号是否属于该块、摘句是否是原文子串。
- 各块的 system prompt 完全相同，块内容放在 user 消息，让请求开头一致，能命中提示词缓存。
- 关闭思考模式：DeepSeek 默认开着思考，思考内容计入输出 token，而且开着思考时不接受指定工具。关闭方式因提供商而异，写进预设，没有的不发送。提供商仍拒绝指定工具时改用 `auto` 重发。
- 放弃：让模型输出所有引用的摘句（输出 token 多）；不发用户名等字段（用户否决）；Agent 循环加 `submit_findings` 工具（多一次调用）。

- `npm run typecheck` 通过。
