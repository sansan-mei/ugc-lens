## 设计决定

- 先用代码算出能算的（关键词、重复次数、高峰时段、覆盖率），再交给模型总结：结果稳定、不花 token，也让报告里的数量有据可查。
- 沿用 media_crawl 的分词方案（`Intl.Segmenter` + 词典保护 + 停用词 + 每条只计一次），但词典不从远程下载，而是用新词发现从这批数据里找，不需要维护词库。
- 区分度用对数几率比，而不是直接比较词频或 TF-IDF：低频词不会因为偶然出现一两次就排到前面。
- 高峰检测用中位数和 MAD，而不是均值和标准差：一个极端高峰不会让其他高峰变得“不显著”。
- 复读合并和刷屏压缩：B 站评论区大量复制粘贴的内容，不合并时会占满预算，模型也看不到其他声音。合并后注明重复次数，“很多人说同一句话”这个信号保留下来。
- 超出预算时 30% 按热度保留、70% 随机抽样，并固定随机种子：既保证高赞内容一定被看到，又避免只看高赞造成的偏差，同一份数据每次分块结果相同。
- 不引入情感模型、CES 刷量检测阈值和向量聚类，原因见架构文档第 6.1 节。

## 验证

- `npm run typecheck` 通过。
- `npm test`：210 个用例全部通过。
- `npm run smoke` 通过。
- 真实数据（不调用模型做分析）：
  - 荒野独居视频（7987 条）：新词发现找到“打火石”“学院派”“原住民”“谢甲催”“家人侠”等；弹幕 7036 条去重后 3399 条，高峰 02:35-02:40（311 条，平时每段约 98 条），高峰里是“老威”“老佩”等选手名。全部 951 条评论和回复都放进 9 块，弹幕 308 组代表 3839 条。
  - 测肺活量视频（98381 条）：一级内容 90260 条，合并复读 78548 条，抽样放进 1931 条；新词发现约 90ms，关键词约 350ms，分块约 200ms。
- 没有验证：知乎、小红书数据上的新词发现效果；英文内容（`Intl.Segmenter` 能分，但停用词表只有中文）。
