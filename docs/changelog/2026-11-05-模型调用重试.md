## 设计决定

- 重试放在模型客户端，循环不关心。循环只通过 `onRetry` 收到通知并转成事件。
- 只有明确标记 `retryable` 的错误才重试。返回内容不是 JSON、`choices` 为空这类错误不重试：它们通常说明接口地址或代理配置有问题，重试没有意义。
- 调用方的 `signal` 触发后一律不重试，原样抛出取消错误，循环据此判断是 `aborted` 还是 `timeout`。
- `Retry-After` 超过 60 秒时不照办，改用退避时间，避免一次等待太久；代价是可能再次收到 429，但次数有上限。
- 参考 OpenAI 官方 SDK 的做法：408、429、5xx 重试，抖动最多减少 25%。409 不重试，因为国内提供商很少使用这个状态码。
- 不做主动限速，等流水线需要并行调用时再做。
- token 预算保持软上限，没有改成按预估用量提前停止，先如实写进文档，由用户决定是否改严格。
