# 通用文本格式导入

- 日期：2026-11-05
- 关联步骤：roadmap 第 9.5、14 步

## 改动内容

- 新增 `src/ingest/formats.ts` 和 `errors.ts`，统一读取 JSON、JSONL/NDJSON、CSV/TSV、TXT、Markdown、LOG，沿用 100 MB 上限，支持取消、UTF-8 和带 BOM 的 UTF-16 LE/BE；不新增依赖。
- CSV/TSV 支持表头、引号内换行、双引号转义和空单元格；内部稳定列键对应原始表头，字段由模型识别。表头名称和顺序参与缓存指纹，不跨不同表头复用规则，防止识别错列。
- 纯文本和字符串数组使用内置映射，不调用模型识别格式或创建映射缓存；TXT/LOG 按非空行、Markdown 按段落，生成来源行号 ID。
- 统一数据类型新增 `record`，查询、统计、分块、提示词和报告支持问卷、评价、工单、访谈等通用记录；默认分析方向支持通用主题，保留短答案和长记录，不套用评论的低信息过滤与 500 字截断。
- CLI 区分内置、模型识别和缓存；持续对话和 MCP 共用导入器，MCP 无配置也能导入和查询纯文本。监听默认仍匹配 `*_all.json`，支持显式选择其他格式。
- 更新 README、架构、路线图和宿主技能；第 9.5、14 步勾选完成，版本升为 0.0.6。CI 在安装后的包上运行通用格式 CLI 和 MCP 验证。

## 设计决定

- 复用现有映射推断、缓存、统计和分析流水线，避免给每种格式另做分析逻辑。CSV 保留单元格字符串，再根据字段规则转换已知元数据，防止前导零 ID 被破坏。
- 表头需要唯一且非空，坏 JSONL 行、错列、未闭合引号和非法编码都明确报错，不自动跳过损坏数据。CSV 内容作为数据处理，不执行公式或命令。
- 长通用记录保留全文，单条超过分块软上限时独立成块，但仍受总字数预算限制；放不下的记录体现在报告覆盖率中，不伪装成全文已分析。
- 本次不引入 Excel/PDF/Word 等二进制文档解析，也不做数值表格计算。GBK 等编码需先转换为 UTF-8。
