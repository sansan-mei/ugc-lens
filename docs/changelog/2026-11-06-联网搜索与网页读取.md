# 联网搜索与网页读取

- 日期：2026-11-06

## 改动内容

- 新增 `src/web/`：
  - `config.ts`：`web` 配置读取、开启判断及端点与 key 的绑定校验。
  - `search.ts`：SearXNG（`GET /search?format=json`）与 Tavily（`POST /search`）后端，统一结果字段，处理错误、限流、非法响应和超时。
  - `fetch.ts`：只读网页抓取，连接时校验解析地址（SSRF 防护），重定向逐跳校验，限制大小、超时与内容类型，支持压缩和 GBK 等编码，用 Readability + linkedom 抽取正文。
  - `cache.ts`：带过期时间的本地缓存，原子写入，损坏按未命中处理。
  - `tools.ts`：`web_search`、`web_fetch` 工具与联网会话（`web:N` 来源编号、不可信标记、次数上限），`guardAfterWeb` 写入门禁，`findWebCitations` 外部引用核对，`WEB_PROMPT` 规则。
- `src/agent/usage.ts` 任务账本新增 `web` 计数；`src/store/tasks.ts` 同步可选字段。
- `src/tools/approval.ts` 新增 `after_web` 审批种类，`src/cli/approve.ts` 补充提示文字。
- `src/dataset/query.ts` 的 `findCitations` 不再把 `web:N` 当作编造的数据 ID。
- `src/ask/index.ts`、`src/chat/session.ts` 接入可选的联网会话：追加联网规则、提供工具、写入工具加门禁、返回 `web_citations`。
- 命令行：`ugc-lens --web`、`ask --web`、`mcp --web`；`src/cli/index.ts` 允许以选项开头进入对话。MCP 只把联网用于服务内部的 `ask`，每段对话复用同一联网会话。
- 新增依赖 `@mozilla/readability@0.6.0`、`linkedom@0.18.15`（`bun add`，更新 `bun.lock`）。
- 导出新的代码 API；README 新增“联网搜索”一节；`skills/ugc-lens/SKILL.md` 说明 `web_citations`；架构文档第 2.7 节与工具清单、路线图第 16 步同步。

## 设计决定

- 搜索后端直接用 `fetch`，不引入 `@tavily/core`：请求简单，便于本地模拟测试，也少一个依赖。路线图原先写的官方 SDK 方案改为此方式。
- SSRF 用内置 `lookup` 在连接时校验，不引入 `request-filtering-agent`；Node 内置 `fetch` 不能挂这个 agent，改用 `node:http(s)` 能在连接时校验，也避免解析与连接之间被换成内网地址。
- 开启联网只认 `--web`、`UGC_LENS_WEB` 和全局配置：开启后数据内容可能经搜索词或网址外传，不应由项目目录替用户决定。
- MCP 不向宿主暴露联网工具，只供内部 `ask` 使用：宿主通常自带联网，重复提供只会多一条注入路径。
- 写入门禁按“对话中是否已有网页内容”判断，而不是按单个任务判断：网页内容留在历史里，后续轮次同样可能受影响。
- 搜索结果也编号为来源（正文为摘要），读取网页后同一 URL 换成页面正文，编号不变。
- 残余风险：被分析数据中的注入文字仍可能诱导模型把数据写进搜索词或网址。无法在工具层完全阻止，因此默认关闭并在文档中提示。

## 验证

- TDD：先写 `test/web/` 下的配置、搜索、网页读取、工具与 ask 集成测试，确认因模块缺失而失败，再实现。另补充会话、MCP 和命令行参数测试。
- SSRF 覆盖回环、私网、metadata、运营商 NAT、零地址、IPv4 映射与 NAT64 地址、整数形式 IP、`localhost`、DNS 解析到内网、重定向到内网和非 http 协议。
- 注入覆盖：网页要求写入画像时 `record_profile` 被拒绝；延续的历史中有网页内容时同样被拒绝。
- `npm run typecheck` 通过；隔离 HOME 后全量 `node:test` 通过，`git diff --check` 通过。
- 测试中的网络均为本地模拟服务。未用真实 SearXNG 或 Tavily 验收搜索质量，未运行真实模型 smoke，未构建、打包或发布。
