# 桌面单文件包原型

- 日期：2026-11-11
- 关联步骤：roadmap 第 19.1 步

## 改动内容

- `scripts/sea.ts`：把 `dist/`、`ui/`、`playbook/`、`skills/`、`package.json` 和生产依赖压成 zip，生成 SEA 配置并用 `node --build-sea` 出可执行文件；去掉类型声明、源码映射和 `.bin`。
- `scripts/desktop_entry.mjs`：单文件包入口，放在虚拟文件系统根目录，处理双击启动参数后加载 `dist/cli/index.js`。
- `src/cli/desktop.ts`：双击启动（没有参数，或只有 macOS 的 `-psn_` 参数）时改为 `ui --cwd ~/ugc-lens`，其余参数原样交给命令行。
- `scripts/desktop_smoke.ts`：冒烟检查 `--version`、`--help`、`playbook`、界面首页和全部静态资源。
- `.github/workflows/desktop.yml`：手动触发（以及推送 `sea-prototype` 分支），macOS arm64 出 dmg（.app 本机临时签名，LZMA 压缩的 ULMO 格式），Windows x64 出 zip，体积写进运行摘要，产物作为 artifact 保存。
- `.gitignore` 忽略 `build/`；roadmap 新增第 19.1 步，architecture 技术选型表新增桌面包一行。

## 设计决定

- 不用 Electron：运行时压缩后约 100MB 以上。也不用 Bun 编译：官方运行时压缩包比 Node 还大，且运行时与开发测试用的 Node 不一致。
- 选 Node 26 的虚拟文件系统：现有代码用 `import.meta.url` 读取内置手册、界面文件和版本号，放进虚拟文件系统后路径关系不变，不用改这些代码，也不用 esbuild 打包。Node 22/24 的 SEA 只能加载内置模块，必须打成单个 CommonJS 文件，留作退路。
- 生产依赖用 `bun install --production --frozen-lockfile --linker hoisted` 单独装，版本跟 `bun.lock` 一致，平铺目录避免符号链接。
- 运行时只关闭 `ExperimentalWarning`，其它警告保留。

## 验证

- 先写 `test/cli/desktop.test.ts`、`test/scripts/sea.test.ts`，确认因模块不存在而失败，再实现；新增 7 个用例通过。
- `npm run typecheck` 通过；全部测试 553 个通过（本机 Node 26.12.1，HOME 指向临时目录）。
- 本机 Linux x64 实际打包：归档 1310 个文件 3.4MB，可执行文件 147.1MB（gzip 48.3MB、xz 33.4MB）；冒烟检查通过，另外验证了无参数启动进入界面并创建 `~/ugc-lens`、`host describe` 读取 B 站样例、字体以 `font/woff2` 返回，没有实验功能警告。
- `desktop.yml` 在 macOS 15 arm64 和 Windows Server 2025 上构建并通过冒烟：mac 可执行文件 143.2MB，dmg 用 ULFO 格式时 46.6MB；Windows exe 99.0MB，zip 41.3MB。dmg 随后改为 ULMO 格式，体积以后续运行摘要为准。
- 真机双击体验未验证。

## 后续

- 原型只用 .app 包一层：没有图标，双击后在后台运行（`LSUIElement`），退出要用活动监视器；Windows 双击会带一个控制台窗口，关掉即退出。
- 没有开发者签名和公证：从网上下载的 dmg 需要在系统设置里放行，Windows 会弹 SmartScreen。
- 界面里还不能填模型密钥，先用命令行 `ugc-lens init` 或全局配置文件。
