# 同内容文件优先读缓存

- 日期：2026-11-14
- 关联步骤：roadmap 第 19 步、第 5 步（导入规则缓存）

## 改动内容

- 结构识别规则：`src/ingest/index.ts` 的 `loadDataset` 新增 `sharedCacheDir`，先查项目缓存 `<启动目录>/.ugc-lens/mappings`，再查共享缓存，新规则两边都写。`src/config.ts` 新增 `sharedMappingsDir()`（`~/.ugc-lens/mappings`）。界面打开文件、界面对话（含恢复对话时的重新导入）、命令行 `chat`/`ask`/`analyze`/`watch`/`host`、MCP 服务都传入共享缓存；`ChatSession`、`McpServerOptions` 增加 `sharedCacheDir` 选项。
- 内容摘要：`Dataset` 新增 `content_digest`，由导入格式和解析后的数据计算，与路径和排版无关。
- 自动分析结果：`src/ui/analysis.ts` 改为按内容摘要存到 `~/.ugc-lens/ui/analysis/<内容摘要>/`，同样内容的文件在任何位置、任何启动目录打开都先读已有结果；结果记录分析时的条数，条数对不上不复用；运行中的任务按内容记，不会重复跑。早期写在 `<启动目录>/.ugc-lens/ui/analysis/<数据集 ID>/` 的结果仍可读取。运行器的 `status`、`results` 改为接收数据集。
- `docs/architecture.md` 第 2.1 节、第 5 节缓存说明同步。

## 设计决定

- 共享缓存由入口层显式传入，`loadDataset` 默认不读写主目录：库调用和测试不会碰到用户主目录（测试后确认 `~/.ugc-lens/mappings` 未被创建）。
- 结构规则仍按结构指纹缓存（同结构不同内容也能复用）；分析结果按内容摘要缓存（内容相同才复用），两者粒度不同。
- 内容摘要用解析后的数据而不是原始字节：同一份 JSON 只是缩进不同也视为同一内容。
- 数据集 ID 仍按路径计算，不改：对话历史里的 ID 依赖它，改动会让已有对话失效。
