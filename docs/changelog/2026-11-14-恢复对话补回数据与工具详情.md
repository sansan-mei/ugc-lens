# 恢复对话补回数据与工具详情

- 日期：2026-11-14
- 关联步骤：roadmap 第 19 步

## 改动内容

- 修复：服务重启或会话被回收后继续历史对话，模型之前用 `load_dataset` 导入的数据不在内存里，模型拿着旧 `dataset_id` 查不到，只能去启动目录重新找文件（用户截图中的“未打开数据”、找不到简历笔记）。
  - `src/ui/chat.ts`：新增 `datasetsInHistory`，从历史的工具结果中找出导入过的文件；恢复会话时连同界面接入的文件一起重新导入并 `attach`，本轮回答前等待完成，失败以 `warning` 提示。重新导入复用会话已有的分析模型。
  - `chats/<id>` 对没有记录 `dataset` 的对话（早期对话、只由模型导入的对话）取历史里最后导入的文件，切回对话时界面同样能自动重新打开。
- 工具详情：
  - `src/agent/events.ts`、`src/agent/loop.ts`：`tool_end` 事件带工具结果 `result`。
  - `src/ui/chat.ts`：`tool` 事件的参数上限从 300 字改为 4000 字，`tool_end` 带结果（最多 8000 字，超出截断并注明总长），一并保存到历史。
  - 前端：工具标签可点击，弹窗显示请求参数和返回结果（JSON 缩进显示，`web/src/lib/chat.ts` 的 `prettyJson`）；工具运行中打开时，结束后自动显示结果。
- `docs/architecture.md` 第 2.1 节补充事件字段与恢复时重新导入。

## 设计决定

- 从工具结果而不是工具参数找文件：结果里的 `file` 是解析后的绝对路径，参数可能是相对路径或错误路径；只认同时带 `dataset_id` 和 `file` 的结果，导入失败的调用不会被当成数据集。
- 不把数据集序列化进历史：文件可能很大，且源文件更新后应读最新内容；数据集 ID 按路径计算，重新导入后历史里的 ID 仍然有效。
- 工具结果保存截断版：完整结果已在模型历史里，界面记录只用于查看，限制长度避免历史文件过大。
