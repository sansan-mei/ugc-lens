- `src/ui/server.ts`：新增 `GET /api/ping`（心跳，返回启动目录）和 `POST /api/quit`（先返回再调用 `onQuit`，没有提供时返回 501）；记录进行中的请求数与最近活动时间（`activity()`）。
- `src/ui/instance.ts`（新）：桌面实例记录 `~/.ugc-lens/ui/instance.json`（权限 600）的读写、只删除自己写的记录、用令牌请求 ping 判断实例是否可复用、空闲判断。
- `src/cli/ui.ts`：拆出可测试的 `startUi`；新增 `--desktop`：写实例记录、10 分钟无请求自动退出、退出时清理记录；网页“退出”在命令行启动时同样可用。

- `scripts/desktop/icon.ts`（新）：纯 Node 画出应用图标 PNG（与界面标志一致）；`desktop.yml` 用 sips、iconutil 生成 `.icns` 并写入 `CFBundleIconFile`。
- `scripts/desktop/打开前必读.txt`（新）：随 dmg 附带的安装、放行、退出说明。
- `docs/architecture.md` 第 2.1 节补充“退出与桌面单实例”；`docs/roadmap.md` 第 19.1 步更新状态与真机笔记。

## 设计决定

- 单实例放在双击启动器里，而不是服务里：macOS 对已在运行的应用再次双击只会激活，不会再启动进程，单文件 Node 程序也收不到“重新打开”事件，服务端再怎么判断都拿不到第二次双击。启动器每次都退出，所以每次双击都会执行。
- 判断实例是否存活用令牌请求 ping，不看 pid：pid 可能被复用，端口可能被别的程序占用。
- 空闲退出只在 `--desktop` 下启用，npm 版 `ugc-lens ui` 行为不变；心跳 60 秒、空闲 10 分钟，后台标签页的计时器被浏览器放慢到每分钟一次也不会误判。
- 图标用代码画而不是提交二进制：仓库里不放图片文件，改图标只改脚本。放弃了在 CI 里用 qlmanage 渲染 SVG 的方案，系统间行为不稳定。
- 放弃 shell 脚本做启动器：入口仍是同一个已签名的单文件可执行程序，Windows 上也能用同一套逻辑。

## 验证

- `npm run typecheck` 通过；`npm test` 579 项全部通过（新增 instance、cli/ui、desktop、server 的 ping/quit、前端心跳、图标与 PNG 编码、dmg 说明一致性测试）。
- 本机用 `npm run build` 的产物和一个转发脚本模拟双击（隔离 HOME、替换 `open`）：第一次启动服务，第二次复用（只有 1 个进程，浏览器打开同一网址），网页退出后进程结束、记录删除，再双击重新启动。
- 内置浏览器里点击“退出”，服务停止，页面显示已退出提示。
- 本机生成图标并用 iconutil 转成 .icns 成功，目视检查正常。
- 未验证：本机 Node 24 无法构建 SEA，真正的 dmg 需要运行 desktop.yml 后在真机复验；`npm run smoke` 需要真实模型接口，本次未运行（改动不涉及模型调用）。
