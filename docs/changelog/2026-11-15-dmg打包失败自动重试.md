# dmg打包失败自动重试

- 日期：2026-11-15
- 关联步骤：roadmap 第 19.1 步第 4 项

## 改动内容

- `.github/workflows/desktop.yml`：macOS 打包中的 `hdiutil create` 包进重试循环，最多 4 次，间隔 15、30、45 秒；每次重试前删掉残留的 dmg；4 次都失败时步骤失败。
- `test/scripts/release.test.ts`：新增测试，检查 `hdiutil create` 在重试循环里、至少尝试 3 次、最后仍失败时退出码非零。

## 设计决定

- 0.0.20 发版时 macOS 打包报 `hdiutil: create failed - Resource busy`，同一提交单独运行的打包成功，重跑失败的 job 后通过，属于 GitHub macOS 运行器上磁盘映像服务的偶发占用。重试比每次手动重跑省事，也让发版一次跑完。
- 只重试 `hdiutil create` 这一步，不整体重跑打包，失败点之外的步骤不受影响。

## 验证

- TDD：先写测试；还原工作流改动时测试失败，加上重试后通过。
- 把重试脚本从工作流里取出，用假的 `hdiutil` 在本机跑：前两次失败、第三次成功时产出 dmg、退出码 0；一直失败时尝试 4 次后退出码 1、没有 dmg。
- `npm run typecheck` 通过；`npm test` 620 项全部通过。
- 没有在 GitHub Actions 上实际复现 Resource busy；推送后桌面打包工作流会跑一次正常路径。
- 没有运行 `npm run smoke`：只改工作流，不涉及模型调用。
