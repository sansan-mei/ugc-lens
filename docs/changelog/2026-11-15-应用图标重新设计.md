# 应用图标重新设计

- 日期：2026-11-15
- 关联步骤：roadmap 第 19.1 步（桌面单文件包）

## 改动内容

- `scripts/desktop/icon.ts`：图标改为深色圆角方块上的白色放大镜，镜片里是三行“评论”，分别用绿、黄、红三色（对应界面情感分布的正面、中性偏黄、负面），表达“从原文里看清反馈”。仍按 macOS 图标网格留边距、超采样抗锯齿。
- 同一脚本新增 `.ico` 输出（`encodeIco`、`iconFile`、`ICO_SIZES`）：内嵌 16～256 共 7 个尺寸的 PNG。输出格式按扩展名决定。
- `.github/workflows/desktop.yml`：Windows 打包前生成 `build/ugc-lens.ico`，以 `/DIconFile` 传给 Inno Setup。
- `scripts/desktop/ugc-lens.iss`：安装程序图标（`SetupIconFile`）、开始菜单和桌面快捷方式（`IconFilename`）、卸载项（`UninstallDisplayIcon`）都使用这个 `.ico`，`.ico` 随程序装到安装目录。缺少 `/DIconFile` 时编译报错。
- `test/scripts/desktop_icon.test.ts`：新增 ICO 编码、按扩展名输出、Windows 安装包使用图标三项测试。

## 设计决定

- 之前的光圈图标与界面左上角标志相同，但看不出是做什么的；放大镜加彩色评论行更直接，16 像素下也能分辨。
- Windows 之前完全没有图标，安装包和快捷方式都是系统默认图标。
- 没有给 `ugc-lens.exe` 本身写入图标资源：SEA 程序数据是注入到 PE 资源里的，改资源要引入 rcedit / resedit 之类的依赖，还有破坏注入数据的风险。用户实际接触的是安装程序和快捷方式，这两处已经有图标。
- 仍然不在仓库里放二进制图标文件，打包时由脚本生成。

## 验证

- TDD：先写测试，确认因导出不存在而失败，再实现。
- `npm run typecheck` 通过；`npm test` 616 项全部通过。
- 本机生成 1024 PNG 与 `.ico`，按工作流同样的 `sips` + `iconutil` 步骤生成 `.icns` 成功；`sips` 能读出 `.ico`（最大 256 像素）。查看了 1024 与 32 像素效果。
- 没有在 Windows 上实际运行 Inno Setup，需要等桌面打包工作流在 CI 上跑一次确认。
- 没有运行 `npm run smoke`：只改打包脚本，不涉及模型调用。
